# 边界与已知限制

这个文档记录**做过但没做好的事**，以及**不该做的事**。写出来是为了让后来者不重复踩坑。

## 一、法律与许可

### SnowLuma 不能自动部署

它的 EULA 明确写了：不得把本体并入第三方安装包、不得通过自动化脚本部署。所以：

- 本仓库**不打包**它的任何文件
- 安装脚本**不会**帮你下载或启动它
- 部署文档要求你**手动双击 `launcher.bat`**

违反的后果不只是失效，可能连带 QQ 账号。别图省事。

### 音色模型不能公开分发

RVC 模型（游戏角色、动漫角色、真人）的**声音权利属于原作方或本人**。社区分享的模型多数处于灰色地带：

- 私人场合自娱：一般没人管
- 公开发布、商用、冒充本人：明确侵权

所以本仓库只提供**目录约定和加载代码**，不含任何 `.pth` / `.index`。

本项目实际用到的音色模型，其训练者是 B 站 UP 主 **闪电蘑菇**（[BV16gYS6sE5h](https://www.bilibili.com/video/BV16gYS6sE5h)）。
感谢他把模型公开出来，但**感谢不等于授权**：商用、二次分发、冒充他人仍然不行。

### 豆包语音合成的额度与合规

- 你用的是自己账号的额度，超出会计费
- 合成内容受《生成式人工智能服务管理暂行办法》约束，别用来伪造他人声音

## 二、技术限制

### RVC 唱歌的天花板

| 现象 | 原因 | 能不能修 |
|---|---|---|
| 高音破、撕裂 | 音色模型的训练音域不够 | ❌ 只能换模型或降调（`--pitch -2`） |
| 某些字"卡"一下 | 短音节上掉帧 | ⚠️ 部分能修（补缝 ≤80ms） |
| 咬字发糊 | 换声模型对辅音建模弱 | ⚠️ `protect` 提到 0.9 有改善 |
| 换声后不像原唱的情感 | RVC 只保音色不保表情 | ❌ 换带情感的 TTS 或直接不用 RVC |

**根本原因**：RVC 是把「内容」和「音色」解耦后再合成，解耦过程本身会丢信息。这不是参数能解决的。

### 静音门限的两个失败模式

按参考人声做门限能压掉前奏杂音，但阈值选不好会：

- **太严**：主歌里轻声的字被切掉 → 听起来"断断续续"
- **太松**：前奏的分离残留留着 → 听起来"沙沙的"

当前实现用「先划出整首歌的发声区间，区间内只掐长静音」来规避——牺牲了精确性，换稳定性。

### 洛雪自动化很脆

它没有公开 API（`/search` 需要鉴权且不稳定），所以走 CDP 操作 DOM：

- 依赖 DOM 结构（`class="h0ywb"` 这类混淆类名），**洛雪升级就可能全废**
- 音质弹窗的按钮文本变了也会失败
- 部分源本身下不动（返回 `Invalid URL`），只能逐行试

### CPU 上很慢

**测试机器**（下文所有耗时都在这个配置上测得）：

| 项 | 配置 |
|---|---|
| CPU | **Intel Core i7-9750H**（6 核 12 线程，2.60 GHz 基准，Coffee Lake-H，笔记本） |
| 内存 | 15.8 GB |
| 显卡 | NVIDIA GeForce GTX 1650（4 GB 显存）+ Intel UHD 630 核显 |
| 系统 | Windows 10 企业版 19045 |

**注意：这台机器有 GTX 1650，但实际跑的是 CPU。** 原因见下。

| 环节 | 4 分钟的歌 | 相对实时 |
|---|---|---|
| demucs 分离（htdemucs） | 约 5 分钟 | 1.2× |
| RVC 换声（naxida，索引 98 MB） | 约 15 分钟 | 3.7× |
| 修复 + 混音 + 切段 | 约 2 分钟 | — |
| **合计** | **20~25 分钟** | — |

一句话：**i7-9750H 上，一首 4 分钟的歌要跑 20 分钟以上；这不是配置问题，是 RVC 在 CPU 上的固有开销。**

### 为什么有显卡还跑 CPU

| 原因 | 说明 |
|---|---|
| `rvc-python` 的 CUDA 版在 Windows 上依赖特定 torch 版本 + CUDA Toolkit | 装起来容易把环境搞坏 |
| GTX 1650 只有 4 GB 显存 | 长音频（4 分钟）换声时中间张量会 OOM，需要切片处理 |
| 装完还得回退——一旦 CUDA 版失败，语音链路整个不可用 | 当前是"能用优先"的取舍 |

**如果你想提速**，有两条路（按性价比排序）：

1. **换一台有 8 GB+ 显存的机器**，或租 GPU 云主机跑换声，本地只做分离和混音 → 单首 2~4 分钟
2. **在现有机器上分块换声**（把 4 分钟切成 30 秒一块，逐块换声再拼）→ CPU 上能省 10~20%，但会引入拼接痕迹

> 如果只是想偶尔听，20 分钟一次其实可以接受——反正是后台跑，跑完自动发群。

### 其他机器上的参考

RVC 的 CPU 耗时大致与「单核性能 × 核心数」成反比。按公开跑分粗估：

| CPU | 一首 4 分钟的歌（大致） |
|---|---|
| i7-9750H（本机，6C12T 移动端） | 20~25 分钟 |
| i5-12400（6C12T 桌面端） | 12~15 分钟 |
| i7-13700（16C24T） | 6~9 分钟 |
| Apple M2 Pro（10 核） | 8~12 分钟 |
| RTX 3060（12 GB，GPU） | 1~2 分钟 |

*（粗估，实际受模型索引大小、`index_rate`、音频长度影响）*

### 上下文成本

每次唤醒注入完整人格卡（约 6600 字 ≈ 2000 token）。这是"改卡立即生效"的代价。如果改用 `qq_get_prompt` 按需读取，能省 token，但改了卡不会立刻反映。

## 三、设计上的取舍

| 做了 | 没做 | 为什么 |
|---|---|---|
| 群聊裁剪版感情顾问 | 完整建档问卷 | 群里问 MBTI 太扫兴 |
| 只发第一段翻唱 | 6 段全发 | 刷屏 |
| 提醒只发群消息 | 打电话/推送 | 只做得到这个 |
| 每群独立记忆 | 跨群共享 | 串群很出戏 |
| 短句多气泡 | 长段落 | 长段落立刻像 AI |

## 四、已知 bug / 待办

## 五、如果你要改

几个容易改错的地方：

1. **别在 `# === qq-bridge MCP BEGIN/END ===` 区块里加配置**：`scripts/setup-dsh.mjs` 会整体替换那段
2. **人格卡里不要写括号动作**（`（小声）`）：桥接会把括号内容当正文发出去
3. **改完 `config.json` 必须重启桥接**：白名单、端口、ffmpeg 路径都是启动时读的
4. **改人格卡不用重启**：每条消息重新读文件
5. **批处理文件必须是纯 ASCII**：cmd 用 OEM 代码页读中文会乱码
6. **写 JSON 不要带 BOM**：`Set-Content -Encoding UTF8` 会加 BOM，很多解析器不认
