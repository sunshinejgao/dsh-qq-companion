## 两条音频链路

### 说话（`voice_say`）

```
文字
 → 豆包 TTS（seed-tts-2.0，按 tone 选音色/语速/情感标签）
 → 16kHz 单声道
 → RVC 换声（rmvpe 提音高，protect 0.85）
 → highpass + 3.2kHz 抬一点 + 压缩 + 响度归一
 → 发群
```

耗时约 15–20 秒，主要花在 RVC。

### 唱歌（`cover_song`）

```
歌名
 → 查 covers/ 里有没有 <歌名>-翻唱.mp3
   ├─ 有 → 切段 → 发第 1 段（约 10 秒）
   └─ 没有 ↓
 → 洛雪搜索并下载（CDP 操作 DOM，窗口最小化也能用）
     · 右键菜单 → 下载 → 点音质按钮（这一步最容易失败）
     · 逐行试，直到某个源真的落盘
 → demucs 分离人声 / 伴奏
 → RVC 换声（rmvpe，protect 0.9，index_rate 0.45）
 → 逐帧修复
     · 掉帧补齐 / 去咔哒
     · 按参考人声做静音门限（前奏杂音）
     · 补 ≤80ms 的"卡字缝"（交叉淡化）
     · 频谱减淡 / 去齿音 / 软限幅
 → 混回伴奏 + 响度归一（-14 LUFS）
 → 整首存 covers/<歌名>-翻唱.mp3
 → 按静音间隙切 ≤55 秒
 → 只发第 1 段
```

耗时：4 分钟的歌约 20–25 分钟（CPU）。

## 人格是怎么进到提示词里的

1. qq-bridge 每次唤醒都读 `roles/<当前角色>.md`，**按仿真模式筛小节后整段注入**（上限 `role.maxInjectChars`，默认 8000 字符）。
2. 消息里如果来自 ownerQQ，会在前面标 `【板板】`（原版是 `【管理员】`，本项目改成更贴合人设的标签）。
3. 角色卡之外还有一层**行为提示词**（`qq-chat-v2` 预设），规定怎么调工具、怎么参与群聊——那一层改完需要重启 DSH 才生效。

> 这一点很关键：**人格卡的修改是热生效的**（每条消息重新读文件），而行为层不是。改完没反应，先确认改的是哪一层。

## 多群隔离

```
state/social-v2.json
  conversations:
    "group:<GROUP_ID>":  { wakeConfig, recentMessages, unread, memory... }
    "group:<GROUP_ID_2>": { ... }
```

- 每个群一份唤醒配置、一份上下文、一份轻量记忆
- 工具调用带 `group` 参数，不填会落到默认群（所以角色卡第一节就要求"带当前群号"）
- qq-bridge 启动时读一次 `config.json` 的白名单 → **加群改白名单后必须重启桥接**

## 数据流里的坑（都是踩过的）

| 现象 | 原因 | 修法 |
|---|---|---|
| 新群消息被"忽略未授权会话" | 白名单只在启动时读 | 改完 `config.json` 重启桥接 |
| 改了人格卡她不听 | 卡只在 `qq_get_prompt` 里给全文 | 本项目改成每次唤醒注入 |
| 翻唱前奏有沙沙声 | RVC 在静音段生成噪声 | 按参考人声做静音门限 |
| 唱歌某些字"卡" | 换声模型在短音节上掉帧 | 补缝 + rmvpe + protect 0.9 |
| 洛雪下载没反应 | 窗口最小化，系统级点击落不到 | 改用 CDP DOM 事件 |
| 大图看不了 | 桥接缺 ffmpeg | 配置 `socialV2.voice.ffmpegPath` |
